## 2. Direct answers to the design-question requirements

**"Abstract the WiFi so the UI interface contract stays intact" (C3/C4).** The firmware already funnels every action through a single FreeRTOS queue (`sendCtrlMsg → gCtrlQ`, consumed by `managerTask`), and `serial_cli.cpp` proved the transport pattern. The Android link is simply a **second transport onto the identical queue**: `lib/wifi_link/cmd_dispatch.cpp` parses NDJSON command frames and calls `sendCtrlMsg()` exactly as `dispatch_text()` does — **no new `MsgType`, no `CtrlMsg` change, no backend behavior added.** Provisioning/scan/forget/list/hello are *link/query* frames handled entirely inside `wifi_link` (they never touch the queue). Telemetry flows outward through 11 read-only function-pointer hooks populated in `main.cpp`, so `wifi_link` is fully decoupled from the UI internals.

**"Minimize MCU workload / keep it seamless" (C5).** Signal generation is a hardware gptimer IRAM ISR, *not* a task — it preempts the CPU and cannot be stalled by WiFi I/O. The `wifi_link` task sits on Core 0 at priority 1 (below LVGL and the framework's lwIP tasks), Core 1 stays reserved for the timing-sensitive manager/sweep tasks. Telemetry is coalesced (~8 Hz) and serialized into a fixed static buffer with `snprintf` — **zero per-tick heap**; inbound parsing uses a fixed 256-byte line buffer.

**"Both WiFi modes, user-selectable" (your clarification).** SoftAP fallback (`SignalGen-XXXX`, WPA2, `192.168.4.1`) **plus** app-driven STA provisioning: the phone pushes home SSID+password, the board persists them to NVS (`Preferences` namespace `wifi`) and joins as STA. Because the ESP32-S3 has a **single radio**, the SoftAP is forced onto the STA's channel at association and the AP socket drops — so the design ACKs provisioning *immediately* and the phone re-discovers the board on home WiFi via mDNS (`_siggen._tcp`) or the **manual IP shown on the new LCD link-status label** (never relies on the AP surviving). This single-radio reality was a critical catch from the adversarial review (§4).

## 3. What was implemented (hunk-level)

### Firmware — Agent F (`lib/wifi_link/`, 6 NEW files)
- **`wifi_link.h`** — `WifiLinkTelemetry` hook struct (11 getters + `onLink`) + `wifiLinkInit()`; includes only `<stdint.h>`.
- **`wifi_link.cpp`** — FreeRTOS task (Core 0, prio 1); event-driven STA join (`WiFi.onEvent` GOT_IP/DISCONNECTED, ~15 s timeout) with SoftAP WPA2 fallback (**15-char MAC-derived passphrase, `softAP()` return-checked, asserted ≥8** — D14); `MDNS.begin/addService("siggen","tcp",3333)` only **after** the active interface has an IP; `NetworkServer(3333)` `setNoDelay`, single-client (`accept()` drops prior); non-blocking line assembly; provision ACKs immediately then `WiFi.begin(STA)`; ~8 Hz telemetry into static `s_tel[256]`.
- **`cmd_dispatch.{h,cpp}`** — `cmd_dispatch(jsonLine, emit)`: parses all 12 control frames → `CtrlMsg` → `sendCtrlMsg`, per-frame `ack`. DSL/save strings `malloc`+copy (manager frees); `selNamed` → `findByKey()->name_key` (`.rodata`, **never `strdup`** — D11); catalog via `builtinByIndex(i)` (matches `selBuiltin`), `friendlyName` null-guarded → `name_key`. Includes only the 4 allowed headers.
- **`wifi_creds.{h,cpp}`** — `Preferences` namespace `wifi` (distinct from `siggen`): load/save/clear ssid+pass+provisioned.
- All Arduino/ESP-IDF APIs verified against **arduino-esp32 3.3.4** framework sources.

### 4a. On-hardware bring-up (this session — board flashed via `/dev/ttyACM0`, USB JTAG 303a:1001)
Firmware was built + uploaded to the physical board (`pio ... -t upload`, hash-verified). Serial boot capture confirmed: generator/LittleFS/UI init OK, and **the SoftAP comes up** — `[wifi_link] SoftAP up : ssid="SignalGen-3EBC" pass="siggen-97093EBC" ip=192.168.4.1 tcp=3333`. Two firmware fixes were made and re-flashed during this bring-up (both in `lib/wifi_link/wifi_link.cpp`, Agent F territory):
1. **Spurious `WiFi.disconnect(true)` before init** → `ESP_ERR_WIFI_NOT_INIT` on the no-creds path. Fixed by only disconnecting when a STA join was actually attempted (`staAttempted` guard).
2. **All-zeros SoftAP credentials** — `deriveApIdentity()` called `WiFi.macAddress()` *before* WiFi init, which returns `00:00:00:00:00:00`, yielding the non-unique `SignalGen-0000`/`siggen-00000000`. Fixed by reading the factory MAC from efuse via `esp_read_mac(mac, ESP_MAC_WIFI_STA)` (valid pre-init) → unique `SignalGen-<mac4mac5>` / `siggen-<mac2..mac5>`. Also added a `Serial.printf` success log so bring-up is observable.

Still bench-deferred (needs the phone): the actual phone↔board socket round-trip, provisioning to home WiFi, telemetry, and waveform interactions.

## 6. Deferred / out of scope

- **Board-phase-locked live waveform cursor** (D15): the `edge` counter is a free-running uint16 with no defined zero-phase origin, so the live cursor is **RPM-simulated and labeled "simulated"**. A phase-locked cursor needs an `edge`-semantics contract — future cycle.
- **`MSG_LOAD_TABLE` over WiFi** (capture-replay table push, D12); **WAYPOINT sweep** over the wire; **multi-client** (single phone, D13).
- WebSocket/HTTP transports (raw TCP chosen, D2); OTA/cloud/auth.
- **AGP 9.x / Compose 1.7+/Kotlin 2.x** upgrade — would require new SDK components (build-tools 36 / android-36 / Gradle 9.x) not installed; pinned to the on-disk toolchain (D5). *Note:* Compose **foundation** resolved transitively to 1.7.2 (API-compatible) during the build — no pin change needed, but recorded for reproducibility.
- **Polish deferred to bench feedback:** launcher icon is a placeholder adaptive icon; no app-level ProGuard/R8 (debug build).
