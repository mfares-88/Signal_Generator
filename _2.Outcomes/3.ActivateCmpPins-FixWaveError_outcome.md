## 2. R1 — Answer to the Noise-Spike Question

**Are the spikes normal, or caused by our switching mechanism?**

**Predominantly normal — measurement artifact plus board-level coupling. The gptimer/dedic_gpio engine cannot glitch a held logic level** (re-writing the same value into the output latch each 1 MHz tick produces no edge). One honest nuance: ringing **at the transitions** is excited by our edge — pins ran at default drive (`GPIO_DRIVE_CAP_2`, ~20 mA, 2–4 ns edges) into an unterminated bench lead, a textbook ground-lead-ringing recipe. Hence the implemented mitigation: all generator outputs now run at **`GPIO_DRIVE_CAP_1` (~10 mA)**, softening the edges that excite the ringing while keeping a crisp 0/3.3 V swing.

Run the four falsification tests in plan §4 (ground-spring, LCD-correlation, stopped-output, probe-move) to confirm on your bench. Full reasoning and ranked causes: plan §4.

### E1 — Cam activation (`src/main.cpp`, ±31 lines)

- Boot log now prints all three pins: `[boot] generator init: ... (crank pin=17 cam1 pin=9 cam2 pin=14)`.
- The `USER: SELECT BACKEND OUTPUT PINS` banner rewritten: pins are assigned **once, at the top of the file** (`#define PIN_CKP_OUT / PIN_CAM1_OUT / PIN_CAM2_OUT`, `src/main.cpp:73-77`) — the single user-editable source of truth — each validated by `isValidEsp32S3OutputPin()` with the rejection reason logged. Obsolete 21/22 and crank-only claims deleted.

### E2 — Filter keyboard + fuzzy search (`lib/ui_lvgl/ui_lvgl.cpp`)
- **Keyboard:** one lazy `lv_keyboard` on `lv_layer_top()` — 480×116, bottom-anchored, `TEXT_LOWER`, font forced to `montserrat_14` (project default `dejavu_16_persian_hebrew` lacks the `LV_SYMBOL_*` glyphs). Shows on filter-box FOCUSED/CLICKED; hides on DEFOCUSED/READY/CANCEL (OK and close keys forward READY/CANCEL only to a *bound* textarea — binding happens before unhide). Shared with the DSL textarea; `close_dsl_panel()` hides/unbinds **before** deleting the modal so no dangling pointer survives.
- **Dropdown stays partially visible:** open-list height capped 200 → 120 px (list top ~y 64, keyboard top y 156).
- **Fuzzy search:** allocation-free fzf-lite scorer — case-insensitive subsequence walk, MATCH +4 / CONSECUTIVE +8 / WORD-BOUNDARY +10 / START +12 / GAP −1, `INT_MIN` non-match sentinel, +100 bonus for contiguous substring hits (exact matches always rank top). Scores the max of friendly name and raw key. `name_matches_filter()` is now a thin wrapper, so both existing call sites are unchanged.
- **Ranked lockstep rebuild:** candidates collected per category into a `static` array (`.bss`, off the 8 KB loopTask stack), insertion-sorted by score (stable; skipped when no filter so the unfiltered list keeps library order), then labels and `s_pattern_dd_to_builtin[]` emitted in the same order with the capacity guard before **every** write. `UI_PATTERN_DD_CAP` 128 → 136 (128 builtins + 4 headers = 132 rows; the old cap silently truncated).

### E3 — WAVE bounded renderer (`lib/ui_lvgl/ui_lvgl.cpp`)
- **Root cause eliminated, not patched around:** `on_wave_tick` no longer issues any `lv_draw_*` call (verified: the only remaining `lv_draw_` token is the `lv_draw_buf_t` type). The old path queued up to ~2,600 line draw-tasks per frame into the 64 KB builtin LVGL pool, whose exhaustion made `lv_draw_line` memcpy through a NULL `draw_dsc` (`lv_draw_line.c:66-68`, no NULL check) → the bench `StoreProhibited` at `A2=0/EXCVADDR=0`.
- **New renderer:** RGB565 pixels written directly into the canvas draw buffer via clamped `wave_hfill/wave_vfill/wave_clear` helpers — bounds from `db->header.w/h`, row addressing via `db->header.stride` (bytes), colors packed once via `lv_color_to_u16(lv_color_hex(...))`. Per-column **envelope decimation** (any-high/any-low over the column's slot range) keeps every pattern — including 1,080-slot `audi_135_with_cam` — within O(3 × 432) column writes per tick; fit-mode column↔slot mapping uses `long` arithmetic. 2 px strokes, lane colors, `s_wave_zoom`, `s_wave_lane_mask`, and the 20 Hz cursor are preserved; frame cost ≈ 62 k pixel writes (~1.2 MB/s) — trivial for the 240 MHz S3.
- **Canvas:** 440×160 → **432×144** (lane_h = 48 exact), allocated **PSRAM-first** (frees ~124 KB of internal DRAM while WAVE is open; internal fallback kept). Guards added: NULL draw-buf/data, `cf == LV_COLOR_FORMAT_NATIVE`, cursor `cx < w`. `close_wave_panel` order untouched (timer deleted before buffer free, both on core 1).
