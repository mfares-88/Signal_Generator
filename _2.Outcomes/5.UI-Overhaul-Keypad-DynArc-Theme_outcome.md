## 2. Direct Answer — "Start/Stop shall call begin()/stop()"

Your point 1 asked that the page START/STOP buttons drive the backend's begin/stop. **No `main.cpp` or backend change was needed** — the UI already exposes a single run callback `s_on_run(bool)` wired (in the frozen `main.cpp`) to `MSG_START`/`MSG_STOP` → `gGen.start()`/`gGen.stop()`. Cycle 5 adds the symmetric `ui_force_output_on()` primitive (mirroring the pre-existing `ui_force_output_off()`), so a page START now does **config-message → `ui_force_output_on()`** and a page STOP does **`ui_force_output_off()`**, exactly invoking the backend's run/stop path while the page stays open. (`gGen.begin(pins)` itself remains the one-time boot init in `setup()`; runtime output on/off is `start()`/`stop()`, which is what the buttons should and now do control.)

## 5. Deviations & Follow-ups (faithful report)

1. **Arc "glow" is not a true shadow.** `lv_draw_arc_dsc_t` has no shadow field (verified vendored), so a shadow-glow on the arc indicator is a no-op. Delivered as a bright full-opacity cyan indicator instead. Button/keypad glow (rect shadow) **is** real, confined to primary actions to avoid per-key shadow-buffer churn (`LV_DRAW_SW_SHADOW_CACHE_SIZE=0`).
2. **Keypad per-button glow → press-state glow.** A `lv_buttonmatrix` cannot style individual buttons (one shared `LV_PART_ITEMS`); the cyan glow is applied to `LV_PART_ITEMS|LV_STATE_PRESSED`, giving press feedback on whichever key (incl. OK/Back) is pressed. A true OK/Back-only static glow would require separate `lv_btn` widgets (descoped).
3. **Brief-internal conflicts, followed literally + flagged:** (a) SWEEP Low/High label-vs-value Y-coords are crossed (D14); (b) the HOME LED coordinate (321,15) overlapped the unchanged pattern dropdown, forcing a dropdown/filter reflow (D15); (c) INVERT 95×16 is below the finger-target guideline. All three are bench-confirm items.
4. **Pill / arc-center / direction-glyph coordinates** were chosen by the implementer (the brief said only "below the arc"): Sweep pill (340,188), Comp pill (312,188), Custom pill (340,188); small arc-offset nudges to fit the center value + pill above the bottom button row. Visual-only, trivially adjustable.
5. **Header fonts 18/22/30 left disabled.** Only 12/20/28 are used; the brief's NOTE listed five sizes but no locked widget renders at 18/22/30 — enabling them would be dead flash. Escalation path noted if a larger header is wanted later.
6. **Custom keypad-cursor reset (`s_kp_field_n=0`) was missing** in `open_custom_panel` as shipped by the implementation workflow; **fixed during orchestrator verification** (§3.6). One line; plan-mandated.
7. **`make_spin_row` Custom box width** widened 76→120 px (steppers removed) to match `make_value_box`; public signature unchanged.
8. **Unused `HOME_GAP`/`HOME_BTN` constexprs** remain after the HOME absolute-layout rebuild; harmless (no `-Werror`), optional cleanup.
9. **Spinbox-as-value-box caret:** suppressed via `lv_textarea_set_cursor_click_pos(false)`; if a caret still flashes on tap at bench, the documented fallback is an `lv_btn`+`lv_label` box (same external read API).
