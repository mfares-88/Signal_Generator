### 0.1 What the product is
ESP32-S3 firmware that **generates engine crank (CKP) + cam (CMP) trigger waveforms** on GPIO outputs
for benching/diagnosing ECUs (an "Ardu-Stim"-class signal generator, re-architected). It plays
byte-packed pattern tables out of a hardware-timed ISR, with a touchscreen LVGL UI, a serial CLI, NVS
persistence, sweep + compression modulation, and a runtime pattern **DSL**.

### 0.2 Hardware / board
- **Board:** Guiton **JC4827W543** — ESP32-S3 **N4R8** (4 MB QD flash, **8 MB OPI PSRAM**), 480×272 QSPI
  LCD, GT911 capacitive touch. Display rotation locked **0**; touch `ROTATION_INVERTED` (bench-verified).
- **Signal output pins** (`src/main.cpp:68-71`): `PIN_CKP_OUT=17`, `PIN_CAM1_OUT=9`, `PIN_CAM2_OUT=14`,
  `PIN_CAPTURE_IN=18`. Outputs run at `GPIO_DRIVE_CAP_1`.
- **Board-reserved (do not repurpose):** LCD QSPI 45/47/21/48/40/39, backlight 1, GT911 8/4/3/38,
  SD 10-13, I2S 42/2/41.
- **Cam2 (bit2) is driven by only two builtins** — `gm_ls1_crank_and_cam`, `bmw_n20`. GPIO 14 idling LOW
  on other patterns is correct, not a dead channel.

- **Key flags:** `SIGGEN_BACKEND_TABLE=1` (always — single backend), `BOARD_HAS_PSRAM`,

  LVGL/ESP-IDF API against the vendored source under `.pio/libdeps/esp32-s3-n4r8/`, never from memory.**
- **Current footprint (HEAD):** RAM **34.5%** (113,144 B), Flash **23.6%** (989,031 B). Ample headroom,
  but the LVGL heap is a fixed **64 KB pool** (`LV_MEM_SIZE`, `include/lv_conf.h`) — the real budget.

### 0.4 Runtime architecture (data flow)
```
UI (LVGL task, core 0)  ┐
Serial CLI              ├─ build CtrlMsg ─► gCtrlQ (FreeRTOS queue, depth 16)
                        ┘                         │
                                   managerTask (core 1, prio 3, 8 KB stack)  ← src/main.cpp:687
                                                  │  switch(msg.type) …
                                                  ▼
                          gGen : TableCkpGenerator  (lib/ckp_gen)
                                                  │  apply(PatternRef, rpm) / setRpm / start / stop
                                                  ▼
                     ESP-IDF gptimer alarm ──► ISR ──► dedic_gpio bundle write (CKP/CAM1/CAM2/knock)
```
- **All hardware state changes go through `gCtrlQ`** as `CtrlMsg{MsgType, MsgPayload}` (defined in
  `lib/ui_lvgl/ctrl_msg.h`). Producers (UI, CLI) never touch `gGen` directly. `managerTask`
  (`src/main.cpp:272`) is the sole consumer.
- **Message types:** `MSG_SET_RPM, MSG_SET_PATTERN, MSG_START, MSG_STOP, MSG_SET_INVERT,
  MSG_SELECT_BUILTIN, MSG_SELECT_NAMED, MSG_LOAD_DSL, MSG_LOAD_TABLE, MSG_SET_SWEEP,
  MSG_SET_COMPRESSION, MSG_CAPTURE_START, MSG_CAPTURE_STOP, MSG_SAVE_USER`. (The legacy `MSG_SET_CUSTOM`
  was removed in cycle 6.) `MSG_LOAD_DSL` and `MSG_SAVE_USER` carry **heap-allocated** strings the
  manager must `free()` after consuming.
- **Pattern playback:** a `PatternRef` (`lib/ckp_gen/PatternRef.h`) holds a byte-packed `.table`
  (**bit0=crank, bit1=cam1, bit2=cam2, bit3=knock**), `slot_count` (≤ **4096**), and `degrees` (360/720).
  The ISR walks the table one slot per timer alarm and writes the GPIO bundle.

### 0.5 RPM / timing law (global invariant — fixed in cycle 6)
**RPM is universal CRANK RPM.** `TableCkpGenerator::reprogramAlarm` scales the per-slot period by the
table's degree span:
```
period_us = 60000000 * _table_degrees / (360 * rpm * slot_count)   // uint64, floor-to-1µs
```
`_table_degrees` is set in `apply()` from `ref.degrees` (non-720 → 360) **before** `reprogramAlarm`, so the
sweep `setRpm()` fast path stays correct with no interface change. Effect: 360° CKP-only unchanged; a 720°
table (crank internally **doubled** when any cam is present — `Compiler.cpp` cam-doubling) plays the crank
at the **set** RPM (was 2×) and the cam at **½** crank. Compression `currentCrankAngle()` is ratio-based
(`cycle_time/cycle_dur`) → **invariant** to this scaling. (A parallel *unscaled* copy of the formula at
`CaptureRecorder.cpp:188` is benign — loopback is always degrees=360.)

### 0.6 The pattern DSL (runtime compiler, `lib/dsl/`)
Pipeline: **Lexer → Parser → Compiler → Validator → `DslResult{ok, PatternRef, error, error_offset}`**.
The compiled `.table` is `heap_caps_malloc(MALLOC_CAP_SPIRAM)`; release with `dslFree()` (never on builtin
`.rodata` refs). Grammar (recursive-descent, `Parser.cpp`):
```
<pattern>   ::= <wheel-def> { ":" <wheel-def> }          ; one wheel per channel, colon-joined
<wheel-def> ::= <pin> "," <rot> "," <kind> "," <kind-tail>
<pin>       ::= 1 | 2 | 3 | 4                              ; output channel
<rot>       ::= C (clockwise) | c (counter-clockwise)
<kind>      ::= S (symmetric) | M (missing-tooth) | A (angular)
<sym-tail>  ::= <duty n/d> "," <total-teeth>
<miss-tail> ::= <duty n/d> "," <total-teeth> "," <run-list>   ; <run> ::= <int>("t"|"m"), ≥1 'm'
<ang-tail>  ::= <deg> { "," <deg> }                          ; Σ deg = 360 or 720
```
Validator hard limits: duty `0 < n < d ≤ 32`; missing run-list sums to teeth with ≥1 gap; angular sum =
span; compiled `slot_count` in **2..4096**. The LVGL Custom builder (cycle 6.a) **emits exactly this
grammar** as a string and feeds it through `MSG_LOAD_DSL` — it adds no new backend.

### 0.7 UI structure (LVGL 9.2.2, `lib/ui_lvgl/ui_lvgl.cpp` ~3.5k LOC)
- A 3-tab `lv_tabview`: **`HOME | CUSTOM | ADVANCED`** (`lv_tabview_add_tab` **appends** → tab order = call
  order; no insert-at-index API). 44 px bottom bar.
- **HOME:** pattern dropdown + fuzzy filter (on-screen keyboard), live RPM arc, run control.
- **CUSTOM** (cycle 6.a): the 5-step guided DSL builder — `build_custom_tab` / `render_custom_step` /
  `cb_render_step1..5`, file-static `s_cb` model, helpers `cb_expand_wheel` / `cb_compiled_stats` /
  `cb_emit_dsl` / `cb_validate`. Its Output-Waveform uses **only** `wave_*` direct-pixel helpers on its own
  `cb_canvas` / `cb_canvas_buf` PSRAM statics.
- **ADVANCED:** full-screen overlay pages — **SWEEP / COMPRESSION / WAVEFORM** (the old DSL-EDITOR and
  timer-custom rows are gone). Each overlay has a `< Back` that forces output off.
- Run-control primitives: `ui_force_output_on()` (→ `MSG_START`), `ui_force_output_off()` (→ `MSG_STOP`).
- Modal numeric keypad (`open_numeric_keypad`, file-scope `kKeypadMap`) replaces spinbox steppers; value

### 0.8 Other subsystems

- **`lib/sweep_compression/`** — sweep ramps, compression dip tables, **NVS** persistence (`NvsStore`,

### 0.9 Global constraints / requirements (the hard rules)
1. **RPM = universal crank RPM** (§0.5) — never reintroduce the unscaled period.
2. **Single TABLE backend** — `SIGGEN_BACKEND_TABLE=1` always; no `TimerCkpGenerator` (deleted in cycle 6),
   no dead `#if !defined(SIGGEN_BACKEND_TABLE)` branches.
3. **All state changes via `gCtrlQ`** — UI/CLI never poke `gGen` directly; heap strings in messages are
   freed by the manager.
4. **Bounded ISR + per-frame UI cost** — input-independent, zero unbounded allocation in hot paths (a prior
   class of bench crashes). `slot_count ≤ 4096`, computed with 64-bit products.
5. **No `lv_draw_*` on a canvas** — `lv_draw_line/…` memcpy into an un-NULL-checked task result → 64 KB
   pool exhaustion → StoreProhibited crash. Use the direct-pixel `wave_*` helpers only.
6. **LVGL 64 KB pool is the memory budget**, not flash/PSRAM. Confine shadowed buttons; free canvas PSRAM
   buffers on page/tab leave.
7. **Ownership model (§ below) — only Agent E edits `src/main.cpp`.**
8. **Table byte order is law:** bit0=crank, bit1=cam1, bit2=cam2, bit3=knock.

### 0.11 LVGL 9.2.2 gotchas that bite (verified vs. vendored source)
- `LV_CANVAS_BUF_SIZE` is **4-arg** `(w, h, LV_COLOR_DEPTH, LV_DRAW_BUF_STRIDE_ALIGN)` — not a color-format enum.
- `lv_buttonmatrix_set_map()` **stores the pointer** (no copy) → the map must be `static const char* const`.
- `lv_spinbox` fires **no** `VALUE_CHANGED`; `lv_spinbox_set_digit_format(n)` **clamps range to 10^n−1**
  (teeth box needs 5 digits set *before* `set_range`). Keypad commit writes back via a `KpField.out` pointer
  then re-renders (teardown **before** re-render — the re-render destroys the edited widget).
- `LV_FONT_DEFAULT` lacks `LV_SYMBOL_*` glyphs → symbol widgets must force Montserrat.
- A flex container **ignores per-child `lv_obj_align`**. `lv_tabview` emits `VALUE_CHANGED` only on
  tap/swipe, not programmatic activation. `lv_obj_clean`/`lv_obj_del` do **not** free external canvas
  buffers or `user_data`.

## 2. How the "apply as-is" mandate was honored + the adversarial fixes that mattered

The builder mirrors `docs/ui_overhaul_playground.html` step-for-step: **Channels** (CKP locked + CMP1/CMP2 `lv_switch` toggles + auto rotation chip), **Subtype** (per-channel `Symmetric|Missing|Angular` 3-button segmented control), **Parameters** (conditional fields with live ledgers: Missing `present+missing==teeth & ≥1 m`; Angular `Σdeg==360/720`), **Preview** (Output-Waveform canvas + `slots N/4096 · span`), **Apply** (recap + emitted DSL + APPLY / APPLY+START + status). The builder **emits a colon-joined DSL string** through the existing `MSG_LOAD_DSL` pipeline — **no backend/compiler/`main.cpp` change**.

Adversarial review (planning gate) caught and the plan/implementation fixed several real defects **before** code was written:
- **`LV_CANVAS_BUF_SIZE` is 4-arg** `(w, h, bpp, stride)` in LVGL 9.2.2 — the draft's 3-arg form would not compile. Implemented as `LV_CANVAS_BUF_SIZE(cw, ch, LV_COLOR_DEPTH, LV_DRAW_BUF_STRIDE_ALIGN)`.
- **Keypad-field capacity** miscalc: step-3 renders all 3 channels at once → worst case `3×(3+12)=45` value boxes, not 27 → `s_kp_fields` sized to **[48]** (was going to be 32 → silently-dead fields).
- **Canvas PSRAM leak on tab-switch**: the persistent CUSTOM tab never tears down, so step-4's "free on leave" never fired on a HOME/ADVANCED tap → wired `on_tabview_changed` to `cb_free_canvas()` when the active tab ≠ CUSTOM (idempotent), with **distinct `cb_canvas`/`cb_canvas_buf` globals** separate from the advanced WAVE page.
- **Keypad commit has no event** (`lv_spinbox` fires none) → added a write-back hook: on OK, `*s_kp.out = value` into `s_cb` then `render_custom_step()` (live ledger + waveform), with safe teardown-before-rerender ordering.
- **Teeth capped at 9999** by the hardcoded 4-digit spinbox format → the teeth box uses 5-digit format set **before** the range so 65535 is representable.

## 6. Deferred / out of scope / known limitations

- **CCW cam-reversal in the preview** (phase-only, faithful to the HTML mock): the on-canvas cam-lane edge **order** is indicative for non-palindromic CCW patterns; `slots`/`span` and validity are exact, and APPLY uses the real compiler (surfaced via `g_dsl_error`). Documented in code + a one-line UI note.
- **Per-channel lane name labels inside the canvas** are not drawn (the `wave_*` primitives are pixel-only; no text rasterizer — and `lv_draw_*` is forbidden on the canvas). Lane order is fixed (top=CKP, then CMP1, CMP2) and channel identity is shown in the step-3 cards + step-5 recap.
- **Step-strip pills** show the step number (1–5); the active step name is the body heading (5 names don't fit legibly across 480px). Pills are fully tappable.
- Builder configs are **not persisted** (the HTML builder has no Save/Load; the removed editor's `MSG_SAVE_USER` flow went with it).
- Pre-existing latent: `make_value_box`'s "Interval us" field is still 4-digit-capped at 9999 (not a builder field) — noted for a future fix.
