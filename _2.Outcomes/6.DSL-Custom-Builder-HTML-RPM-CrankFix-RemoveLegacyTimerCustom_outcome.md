## 2. Direct answers to the question-type requirements

**"Apply RPM to the CKP signal whether isolated or with a 720° CMP" (R2).** Done by a single coherent rule: **RPM = crank RPM, universally.** The playback period is now scaled by the table's degree span:

```
period_us = 60_000_000 * _table_degrees / (360 * rpm * slot_count)
```

- **Isolated CKP (360° table):** reduces to `60_000_000/(rpm*slot_count)` — unchanged; reads the set RPM.
- **CKP + 720° CMP (720° table, crank doubled internally):** the `720/360 = 2` numerator factor doubles the per-slot dwell → the table (2 crank revolutions) plays over 2 crank-rev-times → **CKP reads the set RPM (was 2×)**, and **CMP reads RPM/2** (cam = ½ crank, physically correct).

**Why the previous code doubled CKP:** the old `60_000_000/(rpm*slot_count)` played the *whole* table in one crank-revolution's worth of time regardless of span; a 720° table contains two crank revolutions of crank teeth (the DSL compiler cam-doubles the crank wheel when any cam is present), so the crank ran at 2×. `lib/ckp_gen/TableCkpGenerator.cpp:354-368`.

**Compression is unaffected:** `currentCrankAngle()` is a pure ratio `cycle_time/cycle_dur` (`SweepCompression.cpp:112-127`); both terms scale by the same factor, so dip timing is invariant to the fix (confirm-only at bench).
