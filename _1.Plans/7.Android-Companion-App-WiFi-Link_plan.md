## 1. Context & Goals

The board (`JC4827W543`, `esp32-s3-n4r8`, Arduino/pioarduino) is an automotive CKP/CMP signal generator with a 3-tab LVGL touch UI (HOME | CUSTOM | ADVANCED). Cycle 7 **adds** an Android phone companion app that talks to the board over WiFi and complements the same HOME/CUSTOM/ADVANCED functionality on a larger screen, with an **interactive waveform** as the centerpiece. The on-board UI stays fully usable; the app is a **UI port over the existing contract**, not new backend behavior.

Every control action already funnels through **one** FreeRTOS queue: `sendCtrlMsg(const CtrlMsg&)` → `gCtrlQ` (depth 16), consumed by the manager task (`src/main.cpp:184-194`). The working `serial_cli.cpp` (498 lines) proves a text-command transport that translates inbound text into `sendCtrlMsg()` calls. **The WiFi link replicates that role over TCP** — a second transport onto the identical queue, never a new backend.

**Goals**
1. **Firmware:** a self-contained `lib/wifi_link/` (Agent F) running a low-priority FreeRTOS task on Core 0 that (a) brings up WiFi (SoftAP fallback + STA provisioning, creds in NVS), (b) advertises mDNS `_siggen._tcp`, (c) accepts a single TCP client, (d) parses inbound NDJSON commands → `sendCtrlMsg()`, (e) pushes NDJSON telemetry at 5–10 Hz — all with **zero hot-path heap** and **no new lib_deps**.
2. **Agent E:** surgical `src/main.cpp` adds (telemetry-snapshot accessor + one `wifiLinkInit()` call) **and** a minimal LVGL link-status label in `lib/ui_lvgl/` (IP/SSID/mode) so the manual-IP discovery fallback physically exists. No `MsgType` change; no `sendCtrlMsg` contract change.
3. **Agent C:** confirm flash/RAM headroom for WiFi+lwIP+mDNS via a real before/after linked image against the **2.938 MiB `app0`** partition (`0x2F0000`); no partition resize (creds fit existing `nvs`).
4. **Android:** a single-module Kotlin + Jetpack Compose app under `android/` that builds **headless** to a **signed debug APK**, computes the waveform **locally** from the DSL, and round-trips every control over the NDJSON protocol.
5. **Build green both sides** (`pio run -e esp32-s3-n4r8`; `./gradlew assembleDebug` + `apksigner verify`). On-device/bench verification is **DEFERRED to the user** with a physical phone (§6).

## 2. Execution Model (runtime interaction)

### 2.1 Task / core topology (firmware)
- The generator is a **hardware gptimer IRAM ISR** (`lib/ckp_gen/TableCkpGenerator.cpp:16`), **not a task** — it preempts whatever runs on its core and is **immune to WiFi task scheduling**. Signal timing cannot be stalled by WiFi I/O regardless of pinning.
- Existing tasks: `managerTask` Core 1 prio 3 (`main.cpp:687-688`); sweep/compression Core 1 prio 2 (`SweepCompression.cpp:413-421`); LVGL render + Arduino `loop()`/`serialCliPoll` on Core 0.
- **`wifi_link` task: Core 0, priority 1** (`tskIDLE_PRIORITY+1`), co-located with the framework's lwIP/WiFi RX tasks, **below** LVGL. **Never pin to Core 1** (would risk perturbing manager/sweep). The ISR is unaffected either way.

### 2.2 Single-radio reality (LOCKED understanding — drives the provisioning design)
The ESP32-S3 has **one** 2.4 GHz radio. In AP+STA (APSTA) mode the SoftAP is **forced onto the STA's channel** the instant the STA associates (ESP-IDF documented behavior; `softAP()` defaults to channel 1, `WiFiAP.h:84-89`). The home AP is rarely on channel 1, so at STA-associate time the SoftAP hops channels and **drops every connected AP client** — i.e. the phone's TCP socket to `192.168.4.1` dies exactly when the board joins home WiFi. **Therefore the provisioning flow must NOT depend on the SoftAP surviving STA association.** Coexistence is not seamless and the plan never assumes it is.

### 2.3 AP vs STA flows
- **Boot:** `wifi_link` reads creds from Preferences namespace `wifi`. If a provisioned SSID exists → **STA**: `WiFi.begin(ssid,pass)`, await `GOT_IP` event (via `WiFi.onEvent`, not status-polling) with a ~15 s join timeout. On success → advertise mDNS, push IP to the LCD label + a `link` telemetry frame. On timeout/disconnect → **fall back to SoftAP**.
- **No creds (first run):** **SoftAP** `SignalGen-XXXX` (XXXX = last 2 MAC bytes), WPA2, IP `192.168.4.1`. Android joins via `WifiNetworkSpecifier` + `bindProcessToNetwork`.
- **Single client:** server accepts ONE phone; a new `accept()` drops the previous client. Inbound parse uses a fixed `char[256]` line buffer — no dynamic allocation.

### 2.4 Provisioning sequence (race-safe; SoftAP socket is EXPECTED to drop)
1. Phone joins the board's SoftAP (`WifiNetworkSpecifier`, user approves the system dialog), binds its process to that network, connects TCP to `192.168.4.1:3333`.
2. (Optional) Phone sends `{"t":"scan"}`; board returns `{"t":"scanRes","nets":[...]}` so the user can pick the home SSID and the app learns its **channel** (used in step 4 to narrow the drop window).
3. Phone sends `{"t":"provision","ssid":"<home>","pass":"<pw>"}` (a **link** frame, handled inside `wifi_link` — does NOT touch `gCtrlQ`).
4. `wifi_link` persists SSID+pass to Preferences(`wifi`), sets `provisioned=true`, **immediately** sends `{"t":"ack","ok":true}` (does NOT wait for join), optionally re-creates the SoftAP on the target channel to shrink the disconnect window, then `WiFi.begin(STA)`.
5. **The SoftAP socket may now drop — this is normal.** The phone treats the drop as expected, unbinds the AP network, and **rediscovers the board on home WiFi** via NSD `_siggen._tcp` **or** the manual IP read off the **LCD link-status label** (Agent E). On `GOT_IP` the board (re)advertises mDNS and updates the LCD label.
6. On STA join failure → `wifi_link` reverts to SoftAP and (when the phone reconnects to the AP) emits `{"t":"link","mode":"AP",...}` so the provisioning screen shows the failure and can retry.
7. **Forget:** `{"t":"forgetWifi"}` clears Preferences(`wifi`) and reboots to SoftAP.

### 2.5 Control + telemetry round-trip
- App intent → N1 serializes an NDJSON **command** frame → TCP → `wifi_link` parses → `cmd_dispatch()` builds a `CtrlMsg` → `sendCtrlMsg()` → manager applies → next telemetry frame echoes the new state. Identical to `serial_cli`'s `dispatch_text()`.
- Telemetry: a 5–10 Hz timer in the `wifi_link` task reads the Agent-E snapshot accessor once into locals, `snprintf`s ONE `tel` frame into a fixed static buffer, `client.write()`s it. Per-frame snapshot consistency is acceptable (5–10 Hz, no safety-critical field).
- **Waveform is computed locally on the phone** (§3 D4) — the board never streams compiled slot tables.

## 4. Agent Work Packages (disjoint per agent — parallelizable)

### 4.0 SHARED PROTOCOL SCHEMA — NDJSON (implemented VERBATIM by Agent F **and** Agent N1)

> One compact JSON object per line, `\n`-terminated, UTF-8. Unknown fields ignored. `id` = optional client sequence number echoed in `ack`. Flat fields only (the `sweep`/`comp` fields are flat, not nested objects) so the firmware parser stays hand-rolled and zero-heap.

**Phone → board — CONTROL frames (become `sendCtrlMsg()` calls):**
```
{"t":"rpm","v":2500}                                  -> MSG_SET_RPM  payload.val   (manager clamps 100..6000)
{"t":"start"}                                         -> MSG_START
{"t":"stop"}                                          -> MSG_STOP
{"t":"invert","v":1}                                  -> MSG_SET_INVERT payload.val 0/1
{"t":"selBuiltin","i":3}                              -> MSG_SELECT_BUILTIN payload.val=index (consumed by builtinByIndex, main.cpp:371-372)
{"t":"selNamed","key":"missing36_1"}                  -> MSG_SELECT_NAMED payload.name = findByKey(key)->name_key  (D11)
{"t":"loadDsl","src":"..."}                           -> MSG_LOAD_DSL  payload.name = strdup(src) (manager frees)
{"t":"sweep","lo":600,"hi":6000,"mode":1,"iv":2000}   -> MSG_SET_SWEEP  payload.sweep{low_rpm,high_rpm,mode,interval_us}
{"t":"comp","on":true,"cyl":4,"thr":3000,"peak":100,"dyn":false} -> MSG_SET_COMPRESSION payload.comp{enabled,cyl,rpm_thresh,peak,dynamic}
{"t":"capStart","revs":2}                             -> MSG_CAPTURE_START payload.val=revs   (revs OPTIONAL; absent/0 -> default 2, main.cpp:518)
{"t":"capStop"}                                       -> MSG_CAPTURE_STOP
{"t":"save","key":"myPat","src":"...DSL..."}          -> MSG_SAVE_USER payload.save{name=strdup,dsl_source=strdup}
```
**Phone → board — LINK / QUERY frames (handled INSIDE wifi_link, NOT queued):**
```
{"t":"hello"}            -> board replies link + tel + (optionally) full catalog
{"t":"list"}             -> board replies catBegin / pat… / catEnd
{"t":"provision","ssid":"..","pass":".."}  -> persist creds, ack immediately, WiFi.begin(STA)  (§2.4)
{"t":"scan"}             -> board WiFi.scanNetworks -> scanRes (includes channel for §2.4 step 4)
{"t":"forgetWifi"}       -> clear Preferences('wifi'), reboot to SoftAP
```
**Board → phone frames:**
```
ACK:   {"t":"ack","id":<seq>,"ok":true}
       {"t":"ack","id":<seq>,"ok":false,"err":"<msg>","off":<dsl_error_offset>}   // off only for DSL compile errors
CATALOG: {"t":"catBegin","n":N}
         {"t":"pat","tier":"builtin|user","i":<builtinIndex|-1>,"key":"..","name":"..","deg":360|720,"mask":<channel_mask>,"slots":<slot_count>}
         {"t":"catEnd"}
         // builtin rows: i = builtinByIndex order (matches selBuiltin). user rows: i=-1, select by key (selNamed). name null-guarded -> name_key.
TELEMETRY (5-10 Hz coalesced):
       {"t":"tel","rpm":<sweepCurrentRpm>,"baseRpm":<g_rpm>,"run":<bool>,"pat":"<active name_key>","deg":<degrees>,"mask":<channel_mask>,"inv":<bool>,"edge":<edgeCounter u16>,"cycUs":<full-table cycle_duration_us>,"drop":<gUiMsgDropCount>}
LINK:  {"t":"link","mode":"AP|STA|CONNECTING|DISCONNECTED","ssid":"..","ip":"..","rssi":<n>,"mdns":"siggen","appw":"<softAP passphrase, AP mode only>"}
SCAN:  {"t":"scanRes","nets":[{"ssid":"..","rssi":<n>,"sec":<n>,"ch":<n>}]}
```
Per-channel instantaneous logic level is **intentionally omitted** — the phone derives lanes from its local waveform model; the **live cursor is RPM-simulated** (D15). `cycUs` is the **full table period** (a 720° table spans two crank revolutions per cycle) — Android cursor math MUST use the `deg` field (§4.7).
